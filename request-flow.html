② 聊天链路分阶段详解

按「前端 → 后端 → AI → 返回」四个阶段拆解每一步的关键代码与数据

阶段 1 · 前端发起请求

1.1 用户交互

在 chatbot/index.tsx 选择 Agent（单选）与 Skills（多选），输入消息后 Sender.onSubmit 触发 sendMessage(content)。

1.2 组装请求

sendMessage 取 chatId = threadIdMapRef.current[activeKey]（新会话为空），调用 onRequest({ messages, chatId })。

1.3 改写为 GET

customFetch 取最后一条 user 消息为 input，拼 agent、skills（逗号分隔），发起 GET /models-streaming?input=&chatId=&agent=&skills=。

阶段 2 · 后端处理与 Agent 创建

2.1 入口校验

ModelsLangchainController.test() 校验 input，设置 SSE 响应头（text/event-stream、no-cache、keep-alive），flushHeaders 立即推送。

2.2 加载技能

遍历 skillNames，skillsService.findOne(name) 读取 ~/.makefile_claw/skills/<name>/SKILL.md，过滤 active，重写路径引用后拼接为 skillsContent。

2.3 会话 ID

threadId = chatId || randomUUID()，sessionId = threadId。首次对话生成新 UUID，后续复用 chatId 从检查点恢复上下文。

2.4 创建 Agent

createMakefileClawAgent(agentName, threadId, undefined, skillsContent) 内部：
• FileSaver 绑定 ~/.makefile_claw/memory/<threadId>.json
• readConfigByAgentName 读 agent 配置 → readConfigByModelName 读模型配置 → initStreamModel 创建 ChatOpenAI
• LocalShellBackend 提供文件/Shell 工具
• 组装 finalSystemPrompt = systemPrompt + 终端说明 + skillsContent
• createDeepAgent 编译 Agent（含 todoList + filesystem middleware）

阶段 3 · AI 端流式推理

3.1 发起流式调用

agent.stream({ messages:[{role:'user',content:input}] }, { streamMode:'messages', configurable:{thread_id}, recursionLimit:100, signal })。超时：总 300s / 无活动 90s。

3.2 Agent 循环

deepagents 内部循环：模型输出 reasoning_content（思考）→ 决定调用工具（tool_calls）→ 执行文件/Shell/Todo 工具 → 结果回灌 → 模型输出最终 content（回答）。

3.3 分片结构

每个 chunk 为 [messageChunk, metadata]，含：
• additional_kwargs.reasoning_content — 思考
• content — 正文 / 工具结果
• tool_calls — 工具调用（name/args）
• tool_call_id — 工具结果关联 ID

阶段 4 · SSE 返回与前端渲染

4.1 封装 SSE 分片

emit(text) 输出 data: {"choices":[{"delta":{"content":"..."}}],"sessionId":"..."}。
思考包 <node title="思考">，工具调用包 <node title="执行命令 execute">，工具结果包 <node title="工具结果 execute">，全部嵌在 <think>...</think> 内，正文在容器外。

4.2 流结束

正常结束输出 data: [DONE] + res.end()。finally 中 close() 关闭后端，清空 FileSaver 防抖定时器并立即落盘到 memory/<threadId>.json。异常时下发错误节点分片再 [DONE]。

4.3 前端解析渲染

OpenAIChatProvider 的 onUpdate 回调提取 sessionId → onSessionId 写入 threadIdMapRef。parser 用正则拆分 <think> 块与 <node> 节点，ThoughtChainView 渲染思维链，Bubble.List 渲染正文（XMarkdown + 打字机动画）。

接口清单

  • GET/api/claw/config — 获取完整配置（agents + models + tools），Agents 页一次性加载
  • GET/api/agents — Agent 列表（AgentsService.findAll）
  • POST/api/agents — 新建 Agent（name 唯一，冲突抛 409）
  • PUT/api/agents/:name — 更新 Agent（含启停 active 0/1）
  • DELETE/api/agents/:name — 删除 Agent

数据流说明

页面加载

reload() 调用 getMakefileClawAgentsConfig() → GET /api/claw/config，一次拿到 agents、models、tools 三组数据，分别用于列表渲染和表单下拉。

新建 / 编辑

弹窗表单校验通过后，提取 model.value、tools[].value，组装 payload。编辑走 updateAgent(name, payload)，新建走 createAgent(payload)，成功后 reload() 刷新。

后端读写

AgentsService 通过 ClawConfigService.readConfig()/saveConfig() 读写 ~/.makefile_claw/makefile_claw.json 的 agents 数组，name 为唯一标识。

技能如何注入到对话

聊天页选择

聊天页挂载时 listSkills() 加载已安装技能到多选器，用户勾选后 selectedSkills 持久化到 localStorage（按会话隔离）。发送时 getSkills() 返回当前数组。

后端加载正文

流式接口收到 skills 参数后，逐个 skillsService.findOne(name) 读取 SKILL.md 的正文 content，过滤已停用，重写 ${CLAUDE_PLUGIN_ROOT} 等路径引用，拼接成 skillsContent。

注入 System Prompt

createMakefileClawAgent 将 skillsContent 追加到 finalSystemPrompt 末尾（「【可用技能 Skills】」段落），Agent 在推理时即可遵循技能规范执行任务。
